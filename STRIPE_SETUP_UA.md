# DEMI DEVILLE — Stripe Checkout

Цей архів містить повний сайт із підключенням Stripe Checkout. Не вставляйте ключі у GitHub або вихідні файли.

## Render → Environment

- `DATABASE_URL` — PostgreSQL для товарів, акаунтів, замовлень і медіа.
- `STRIPE_SECRET_KEY` — `sk_test_...` для тесту або `sk_live_...` для реальної оплати.
- `STRIPE_WEBHOOK_SECRET` — `whsec_...` відповідного Stripe webhook (окремий для Test і Live).
- `PUBLIC_SITE_URL` — `https://demideville.com`.
- `PGSSL=disable` — тільки для Internal Database URL у Render в одному регіоні.

Після зміни змінних зробіть Save, Deploy. Створений у Stripe webhook: `https://demideville.com/api/stripe/webhook`, Events: 

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`

Вибрати Snapshot events і Live mode для реальних платежів. Test webhook та test API key використовуються лише разом.

## Поведінка магазину

1. Покупець вибирає Card / Apple Pay / Google Pay у Checkout — кнопка має чорно-білу позначку ✓. Реальна доступність Apple/Google Pay визначається Stripe та пристроєм.
2. Для появи замовлення в особистому кабінеті покупець **має увійти або зареєструватися перед оплатою**. Заповнена форма доставки зберігається тимчасово в браузері до повернення після входу.
3. Натискання **Review order** створює замовлення зі статусом `payment_pending` і перенаправляє на захищений Stripe Checkout.
4. Лише підтверджений Stripe `payment_status=paid` із правильною валютою/сумою міняє статус на `paid`. Повторні webhook не списують залишки повторно.
5. Адмінка → **Заказы** оновлюється приблизно раз на 15 секунд при відкритій вкладці. Видно суму, ім'я, контакти, адресу доставки, склад замовлення та стан оплати. Кабінет `/account.html` містить замовлення користувача.
6. PayPal та Crypto відображаються неактивними, якщо були ввімкнуті в налаштуваннях, оскільки вони **не мають підключених окремих платіжних інтеграцій**. Їх не можна використовувати для створення нібито оплаченої покупки.

## Обов'язкове тестування

- Перевірити повний test-mode цикл на Stripe: реальне відкриття платіжної сторінки, успішну оплату тестовою карткою, `paid` в адмінці, замовлення в `/account.html`, список подій Stripe webhook з HTTP 200.
- Перевірити скасування й помилку оплати (товари залишаються в кошику).
- Лише після цього перемкнути обидва Stripe-ключі на Live та повторно перевірити події webhook.
- Якщо не налаштовано SMTP, листи з підтвердженням можуть не надходити. Збереження замовлення не залежить від роботи SMTP.

Увага: платіжний сценарій перевірено локально з імітацією API Stripe та коректно підписаними тестовими webhook-подіями. Вхід справжнього платежу з реальним Stripe-акаунтом не тестувався в цьому середовищі.
